# 展品互动与评论布局重构设计

## 目标

重构展品弹窗的点赞与评论交互，使 PC 端在展品图片下方集中展示点赞、收藏和分享，移动端
取消说明/评论 Tab，改为连续纵向浏览，并让评论输入框始终固定在弹窗底部。同时增加前端
本地收藏、具体展品分享链接和后端准确评论总数。

## 范围与约束

- 点赞和发表评论继续使用现有后端接口并要求登录。
- 收藏只在浏览器本地实现，不增加数据库表或后端接口，也不要求登录。
- 分享链接使用 `?artwork=<artworkId>`，打开页面后自动展示对应展品。
- 评论总数必须由后端准确统计，不使用当前已加载评论数代替。
- 保留现有评论分页、迟到响应保护、登录重试和安全 DOM 文本写入。
- 不修改 krpano、全景热点数据格式或展馆素材。

## 总体结构

采用一套互动栏 DOM，由响应式 CSS 在 PC 与移动端重新排布。点赞、收藏、评论数和分享只有
一套状态及事件处理，避免两套界面状态不同步。互动栏包含四个逻辑项：

- 点赞：按钮，显示点赞状态及准确点赞数；
- 收藏：按钮，显示本地收藏状态；
- 评论：显示准确评论数，移动端点击后滚动到评论区；
- 分享：按钮，复制当前展品深链接。

PC 端隐藏互动栏中的评论入口，只显示点赞、收藏和分享；评论总数显示在右栏固定标题中。
移动端四项以等宽单行排列。

## PC 布局

弹窗保持固定视口双栏：

- 左栏依次为展品图片、互动工具栏、作品说明；
- 展品图片位置固定，放大、缩小、重置及多图切换行为保持不变；
- 互动工具栏紧贴图片下方，点赞、收藏、分享横向紧凑排列；
- 作品说明独立滚动，不推动展品图片或右栏；
- 右栏顶部固定显示 `观众评论 (N)`；
- 评论列表独立滚动；
- 评论输入框和发布按钮固定在右栏底部。

原右栏点赞按钮移除，所有点赞状态只由图片下方互动栏表示。

## 移动端布局

在宽度不超过 820px，或宽度不超过 900px 且高度不超过 420px 的短横屏中：

- 删除“作品说明 / 评论互动”Tab 及对应切换行为；
- 顶部继续使用当前展品标题和关闭按钮，不新增返回或顶部分享按钮；
- 弹窗主体为单一纵向滚动流：展品图片 → 四等分互动栏 → 作品说明 → 评论标题与列表；
- 互动栏保持点赞、收藏、评论数、分享同一行；
- 点击评论数按钮平滑滚动到观众评论区域；
- 评论输入框固定在弹窗底部，并适配 `env(safe-area-inset-bottom)`；
- 滚动容器预留输入区高度，末尾评论不会被遮挡。

文字说明热点只展示标题与说明，隐藏画廊、互动栏、评论列表和评论输入区。

## 准确评论总数

扩展作品互动汇总结果：

- DAO 的作品汇总查询在一次数据库任务中返回点赞数、当前用户是否点赞及评论总数；
- `ArtworkInteractionResult` 增加 `commentCount`；
- 作品详情 JSON 增加 `commentCount`，原有字段保持兼容；
- 点赞/取消点赞响应无需增加评论数；
- 前端打开作品时读取 `commentCount`，同步更新 PC 评论标题与移动互动栏；
- 当前用户成功发表评论后，本地评论总数加一，再重新加载第一页评论。

评论数表示作品详情成功返回时的数据库准确快照；其他用户之后新增评论不会实时推送，重新打开
作品时会重新取得准确值。

## 本地收藏

收藏状态以 `artworkId` 为键保存到 `localStorage`：

- 使用项目命名空间键保存收藏作品 ID 集合；
- 点击收藏后立即更新星形图标、文字和 `aria-pressed`；
- 再次点击取消收藏；
- 同一浏览器刷新后恢复状态；
- 读取或写入本地存储失败时，降级为当前页面内的内存状态，不阻断弹窗其他功能。

收藏不依赖登录，不与后端点赞概念合并。

## 分享与深链接

分享按钮基于当前页面 URL 生成链接：

- 保留当前地址中其他查询参数；
- 设置或覆盖 `artwork=<artworkId>`；
- 使用 URL API 自动编码作品 ID；
- 优先调用 `navigator.clipboard.writeText()`；
- Clipboard API 不可用或拒绝时，使用临时只读文本框和 `document.execCommand("copy")` 降级；
- 成功后显示“展品链接已复制”，失败时显示明确错误提示。

应用初始化完成后读取 `artwork` 参数并调用现有 `ArtworkModal.open()`。不存在或加载失败的作品
沿用现有错误提示，不影响全景主界面继续使用。关闭弹窗不主动移除 URL 参数，刷新分享地址时
仍会再次打开同一作品。

## 状态与错误处理

- 打开新作品时立即重置点赞数、评论数和分页状态，避免短暂显示上一作品数据；
- 分享、收藏仅在 `currentArtwork` 有效时执行；
- 弹窗关闭或切换作品后，旧的详情和评论响应不得更新互动栏；
- 评论第一页加载失败时保留已有评论、评论数及滚动位置；
- 发布失败不增加评论数；发布成功后只增加一次；
- 文字热点切回普通作品时恢复互动栏、评论和输入区。

## 可访问性

- 点赞与收藏按钮使用 `aria-pressed`；
- 评论定位与分享按钮提供明确 `aria-label`；
- 所有内联 SVG 设为 `aria-hidden="true"`；
- PC 隐藏的评论定位项不进入焦点顺序；
- 移除 Tab 后同步删除 `tablist`、`tab`、`tabpanel`、`aria-selected` 以及移动标签页的
  `inert/aria-hidden` 切换逻辑；
- 评论输入框固定后仍保留可见 label 或可访问名称；
- 复制成功或失败通过现有通知区域反馈。

## 测试与验收

### 后端自动化

- DAO 单元测试验证汇总回调包含准确评论数；
- MySQL 集成测试验证新增/删除测试评论后的汇总计数；
- Service 与 Handler 测试验证 `commentCount` 传播到作品详情 JSON；
- 保持点赞和评论原响应兼容。

### 前端自动化

- 互动栏 DOM 只有一套，PC/移动状态共用；
- 点赞迁移后仍调用原接口并更新数字；
- 收藏可切换、持久化，并在存储异常时内存降级；
- 分享生成编码后的展品 URL，覆盖旧 artwork 参数并保留其他参数；
- Clipboard API 和文本框降级路径均有测试；
- 页面初始化读取深链接并自动打开展品；
- 移动端评论定位、评论数更新、发布失败不增加和发布成功只增加一次；
- 文字热点与普通作品之间切换时状态正确恢复。

### 布局与人工验收

- 静态测试检查 PC 双栏、移动流式布局、Tab 完全移除及固定评论输入区；
- 1440×900：左栏图片下互动栏、右栏固定评论标题和输入区；
- 390×844：四项互动同一行，正文连续滚动，输入区固定；
- 844×390：图片、互动栏和固定输入区均可用，不遮挡导航或内容；
- Android/iOS 软键盘弹出时输入框保持可见；
- 分享链接在新标签页中自动打开正确展品。
