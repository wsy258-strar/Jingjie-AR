# 沉浸式全景展馆界面设计

## 1. 背景与目标

当前轻量前端将场景目录长期放置在页面右侧，压缩了全景画面的可用宽度；场景名称、文字工具按钮等信息也占据了较多视觉空间。此次改造以“全景内容优先”为原则，在不改变后端接口、展馆配置和作品交互能力的前提下，将页面重组为全屏全景画面与少量悬浮控件。

本次设计目标如下：

1. 取消固定右侧场景栏，使全景画面覆盖整个浏览器视口。
2. 使用底部可收起的场景抽屉承载场景切换，浏览过程中自动关闭。
3. 将展馆标题、展馆简介、登录入口和统计数据改为高级、轻量的悬浮玻璃组件。
4. 在右侧提供图标化的全屏、音乐、VR 和视角切换工具。
5. 恢复原版前端的 VR 和四种视角能力，同时避免依赖原版加密配置中的私有动作。
6. 保持桌面端与手机端均可用，并保证现有热点、登录、作品点赞评论和访客统计功能不回归。

## 2. 非目标

本次改造不包含以下内容：

- 不修改后端 API、数据库表结构或 `exhibition.json` 的数据格式。
- 不重新实现 krpano 渲染引擎，也不恢复原版前端框架。
- 不增加第三方 UI、图标字体或 CDN 依赖。
- 不修改作品详情、登录注册和展馆简介弹窗的业务语义。
- 不持久化用户选择的视角模式；页面刷新后恢复为“正常”。

## 3. 方案选择

### 3.1 采用方案：轻量 UI 壳与独立 krpano 适配层

页面布局和交互继续由现有原生 HTML、CSS、JavaScript 轻量前端负责；全景能力统一收敛到 `KrpanoAdapter`。UI 层只表达“进入 VR”或“切换到某种视角”的意图，不直接拼接 krpano 动作字符串。

选择该方案的原因：

- 与当前轻量前端架构一致，改动范围清晰。
- krpano 参数、能力检测和错误处理集中，便于测试。
- 场景切换后可统一恢复当前投影模式。
- 不依赖原版加密 XML 中的 `krpToggleVR`、`krpChangeViewType` 等动作。

### 3.2 未采用方案

1. **直接调用原版动作**：原版通过 `krpToggleVR(true)` 和 `krpChangeViewType(0-3)` 工作，但动作定义位于原版配置中，当前轻量场景 XML 不保证包含这些定义，耦合且难以验证。
2. **重新嵌入原版前端**：会重新引入废弃界面、旧依赖和后端数据源冲突，不符合轻量壳方向。
3. **只改 CSS、不增加适配能力**：可以完成外观改造，但 VR 和视角按钮可能只有 UI 而没有稳定功能。

## 4. 页面信息架构

页面根节点占满视口，全景画布作为最低层，其余组件以悬浮层覆盖：

```text
沉浸式展馆页面
├── 全景画布
├── 顶部悬浮导航
│   ├── 展馆标题
│   ├── 展馆简介
│   ├── 注册 / 登录（登录后显示用户与退出入口）
│   └── 总浏览量 / 当前在线
├── 右侧工具栏
│   ├── 全屏
│   ├── 音乐
│   ├── VR
│   └── 视角切换
├── 视角切换浮层
│   ├── 正常
│   ├── 小行星
│   ├── 鱼眼
│   └── 水晶球
├── 左下角场景选择入口
├── 底部场景抽屉
└── 原有业务弹窗与全局提示
```

固定右侧场景栏、左下角当前场景名称和 `360° PANORAMA` 文案均移除。

## 5. 视觉设计

### 5.1 全景画面

- 全景画面始终覆盖完整视口，是页面的视觉主体。
- 不再因桌面端场景目录而缩窄。
- 控件只在必要区域使用透明背景，不添加覆盖全屏的遮罩。

### 5.2 顶部悬浮导航

桌面端使用三个相互独立的悬浮玻璃分组：

1. 左侧展馆标题：使用轻微金色竖线、低对比细描边和精致中文排版。
2. 中部操作入口：`展馆简介`、`注册 / 登录` 使用独立胶囊按钮。
3. 右侧统计胶囊：总浏览量与当前在线人数并列展示，中间使用细分隔线。

所有分组使用低透明炭黑背景、轻微背景模糊、细描边和克制阴影。不得恢复贯穿整屏的不透明顶栏。

### 5.3 右侧工具栏

- 四个圆形图标按钮垂直排列，顺序为全屏、音乐、VR、视角切换。
- 按钮不显示常驻文字说明，但必须提供悬浮提示、`aria-label` 和清晰的键盘焦点状态。
- 可用、选中、暂停、禁用状态通过图标和背景变化表达。
- 视角切换按钮激活时，与弹出的视角面板形成明确的视觉关联。

### 5.4 场景选择与场景抽屉

- 左下角显示网格图标和“场景选择”。
- 场景抽屉从底部上移，使用透明深色背景承载横向缩略图列表。
- 当前场景使用暖金色边框和高对比状态标识。
- 场景名称仅显示在对应缩略图卡片内，不在页面其他位置重复显示。
- 抽屉关闭后仅保留左下角入口，最大化全景可视区域。

### 5.5 视角切换浮层

- 浮层锚定在右侧视角按钮附近，采用与顶部一致的透明玻璃风格。
- 标题为“视角切换”。
- 四种模式以图标加文字形式横向排列：正常、小行星、鱼眼、水晶球。
- 当前模式使用暖金色高亮；未选模式保持白色低对比状态。

## 6. 交互规则

### 6.1 场景抽屉

场景抽屉默认关闭，并在以下情况打开：

- 点击左下角“场景选择”。

在以下任一情况发生时关闭：

- 再次点击“场景选择”。
- 点击某个场景缩略图。
- 用户在全景区域开始拖动、缩放或点击热点。
- 点击抽屉外部。
- 按下 `Escape`。
- 打开视角切换浮层。

点击场景缩略图后先关闭抽屉，再异步加载目标场景。加载失败时保留当前全景，并显示局部中文提示。

### 6.2 互斥浮层

场景抽屉和视角切换浮层互斥：

- 打开视角浮层时关闭场景抽屉。
- 打开场景抽屉时关闭视角浮层。
- 业务弹窗打开时关闭两者。

### 6.3 全屏

- 全屏目标是整个沉浸式展馆容器，而不是单独的 krpano 画布。
- 进入全屏后保留顶部导航、右侧工具栏和场景抽屉。
- 监听浏览器全屏状态变化，及时更新按钮的可访问名称和视觉状态。
- 不支持或调用失败时显示“当前浏览器无法进入全屏模式”。

### 6.4 音乐

- 当前场景有音乐时，按钮用于播放或暂停。
- 当前场景没有音乐时按钮禁用，并通过提示说明“当前场景暂无音乐”。
- 自动播放被浏览器阻止时保持暂停状态，用户再次点击后重试。
- 切换场景时停止上一场景音频，并加载新场景音频配置。

### 6.5 VR

- `KrpanoAdapter` 负责加载并调用运行时兼容的 WebVR 插件。
- 支持时通过插件动作进入 VR。
- VR 不可用、页面不是安全上下文、设备权限被拒绝或插件未就绪时，返回可识别错误，由 UI 显示中文提示。
- VR 的进入操作必须来自用户点击，以满足浏览器权限和全屏策略。

### 6.6 视角模式

UI 使用稳定的语义枚举，不暴露原版数字编号：

| 模式 | 语义效果 | 关键行为 |
| --- | --- | --- |
| 正常 | 标准透视 | 清除特殊投影，尽量保留当前方向与等效缩放 |
| 小行星 | 立体投影俯视效果 | 平滑转向脚下并拉远，形成小行星视觉 |
| 鱼眼 | 广角鱼眼效果 | 保留当前朝向，增加投影畸变并扩大视野 |
| 水晶球 | 球体包裹效果 | 使用球面投影和适当视野展示环绕空间 |

切换模式使用短时动画，避免画面突变。具体投影参数集中定义在适配层，按当前 krpano 运行时实测校准，不散落在 DOM 事件中。

当前模式保存在页面运行态中：

- 切换场景后，在场景加载完成时重新应用当前模式。
- 刷新页面后恢复为“正常”。
- 模式切换失败时保留上一个成功模式，并显示提示。

## 7. 响应式设计

### 7.1 桌面端

- 顶部分组保持单行悬浮。
- 右侧工具栏使用标准圆形按钮尺寸。
- 场景抽屉尽量展示完整场景列表；超出宽度时允许横向滚动。

### 7.2 手机端

- 顶部控件改为两行悬浮布局，而不是按比例缩小桌面导航。
- 展馆标题保持一行，过长时省略，但完整标题通过可访问名称保留。
- 展馆简介、登录入口和统计胶囊缩小间距，不移除功能。
- 右侧工具栏适当缩小，仍保留足够的触控点击区域。
- 场景缩略图使用横向滑动列表，不压缩成不可识别的小图。
- 视角浮层根据屏幕宽度向内侧展开，避免超出视口。

## 8. 状态与数据流

页面协调层新增以下纯前端运行态：

- `sceneDrawerOpen`：场景抽屉是否打开。
- `viewPanelOpen`：视角浮层是否打开。
- `viewMode`：当前成功应用的视角模式，默认 `normal`。
- `musicState`：不可用、暂停或播放。
- `fullscreenState`：是否处于全屏。
- `vrAvailability`：未知、可用或不可用。

后端数据流保持不变：

- 场景列表继续来自 `GET /api/scenes`。
- 场景详情继续来自 `GET /api/scenes/:sceneId`。
- 总浏览量和在线人数继续使用现有统计接口。
- 作品详情、点赞评论和登录会话继续使用现有接口。

## 9. 代码改动边界

### 9.1 `WebApps/ARServer/www/index.html`

- 将页面重组为全屏画布与悬浮界面。
- 删除固定右侧目录和当前场景标题节点。
- 增加场景抽屉、右侧工具栏和视角切换浮层。
- 使用项目内嵌 SVG 图标，不引入第三方字体图标。
- 保留现有展馆简介、登录和作品详情弹窗。

### 9.2 `WebApps/ARServer/www/css/museum.css`

- 重写全屏布局、悬浮玻璃组件、图标按钮和场景抽屉样式。
- 增加桌面端与手机端响应式规则。
- 增加焦点、选中、禁用和降低动态效果偏好样式。

### 9.3 `WebApps/ARServer/www/js/museum-app.js`

- 渲染底部场景卡片并管理抽屉状态。
- 管理场景抽屉和视角浮层互斥。
- 将音乐按钮从文字状态改为图标状态和可访问名称。
- 管理全屏状态同步、VR 调用和视角切换。
- 删除对右侧场景栏和当前场景标题的依赖。

### 9.4 `WebApps/ARServer/www/js/krpano-adapter.js`

- 增加视角模式枚举、参数映射和模式应用接口。
- 场景加载后重新应用当前视角模式。
- 增加 VR 插件接入、能力检测和进入 VR 接口。
- 对播放器未初始化、插件不可用和调用失败提供明确错误。

## 10. 可访问性

- 所有图标按钮均提供准确的 `aria-label` 和 `title`。
- 打开场景抽屉和视角浮层时更新 `aria-expanded`。
- 当前场景和当前视角分别使用 `aria-current`、`aria-pressed` 表达。
- 所有功能可以通过键盘访问，`Escape` 可关闭临时浮层。
- 不仅依赖颜色表达当前、播放、禁用等状态。
- 遵循 `prefers-reduced-motion`，降低或关闭抽屉和投影切换动画。

## 11. 错误处理

总体原则是“保留全景、局部提示”：

- 场景、音乐、全屏、VR 或视角功能失败时，不替换整个页面。
- 场景目录首次加载失败仍使用现有致命错误重试界面。
- 单个工具失败时通过现有 `notice` 显示具体中文原因。
- 异步场景竞态继续使用 generation 与 `AbortController` 保护。
- 工具状态仅在底层操作成功后更新，避免 UI 与播放器状态不一致。

## 12. 测试与验收

### 12.1 自动化测试

至少覆盖：

1. 场景卡片渲染到场景抽屉且当前场景正确标记。
2. 选择场景、操作全景、按下 `Escape` 时抽屉关闭。
3. 场景抽屉与视角浮层互斥。
4. 四种语义视角正确映射到适配层调用。
5. 切换场景后重新应用当前视角模式。
6. 无音乐场景禁用按钮；播放、暂停状态正确同步。
7. 全屏目标为整个展馆容器，并响应 `fullscreenchange`。
8. VR 不可用和调用失败时显示中文提示。
9. 图标按钮具备必要的可访问属性。

### 12.2 浏览器人工验收

桌面端和手机端分别验证：

- 全景覆盖整个视口，无固定右侧栏。
- 顶部悬浮导航不明显遮挡画面，所有文字来自实际配置。
- 场景抽屉可打开、横向滚动、选择并自动关闭。
- 拖动或缩放全景时抽屉自动关闭。
- 四种视角效果可辨识，切换平滑，场景切换后模式保持。
- 支持设备可进入 VR；不支持设备提示明确。
- 全屏、音乐、登录、展馆简介、热点、作品详情、点赞评论均正常。
- 总浏览量和当前在线人数继续刷新。
- 触控、键盘和窗口尺寸变化下不存在控件溢出或不可点击问题。

## 13. 完成标准

满足以下条件后，本次改造可视为完成：

1. 已确认的桌面端视觉结构和手机端两行布局落地。
2. 右侧固定场景栏及当前场景冗余文字移除。
3. 场景抽屉、全屏、音乐、VR 和四种视角均按设计工作。
4. 自动化测试通过，浏览器人工验收无阻塞问题。
5. 后端接口、展馆配置和现有业务功能无回归。
