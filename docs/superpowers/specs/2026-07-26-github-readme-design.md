# Jingjie-AR GitHub README 设计

## 目标

将项目首页定位为面向面试官和技术招聘方的作品集文档：先在短时间内说明项目价值、技术范围与工程质量，再提供可复现的本地运行和云端部署说明。

## 读者与优先级

首要读者是审阅 GitHub 仓库的面试官。README 依次回答：项目解决什么问题、作者实现了什么、架构如何组织、哪些能力已验证、如何在本地或云服务器运行。

框架使用者和部署者是次要读者，详细操作放在后半部分，避免淹没作品集亮点。

## 内容结构

1. 项目名称、简短定位和技术标签。
2. 项目亮点：自研 C++11 HTTP 框架、Multi-Reactor、异步数据库边界、Session/Redis 回源、A-Frame 360° 全景门户、协作在线人数与互动持久化。
3. 架构概览：浏览器、Nginx、ARServer、HTTP 框架、MySQL、Redis 的职责边界。
4. 功能与 API：匿名浏览、登录后互动、场景进入/退出、心跳和成员轮询。
5. 工程质量：可链接库、测试、集成验证、安全边界和已知部署前提。
6. 仓库结构与技术栈。
7. 本地运行：依赖、数据库初始化、环境变量、构建、启动和测试。
8. Ubuntu 云服务器部署：DNS、ICP 备案提示、systemd、Nginx、HTTPS、更新流程。
9. 贡献、许可证与免责声明。

## 文案原则

- 所有数据与能力均来自当前仓库；不使用无法复现的宣传语。
- 清晰区分框架能力与 ARServer 已接入能力，避免暗示未实现的 WebSocket、AR 识别或场景热点功能。
- 使用 `.env.arserver` 作为本地示例，明确禁止提交密码、令牌和构建目录。
- 部署示例中的域名、IP 和密码均使用占位符。

## 验收标准

- GitHub 首页前屏可看出项目定位、技术栈和主要成果。
- 新读者可依 README 在 Ubuntu 上构建、配置并启动服务。
- README 链接指向仓库内真实文件，命令与实际 CMake 目标、环境变量一致。
- 文档不包含任何真实密码、Token、固定公网 IP 或本机绝对路径。
