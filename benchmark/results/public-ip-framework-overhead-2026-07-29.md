# 公网 IP 端到端 HTTP 压测报告

## 测试范围

- 压测脚本：`benchmark/framework_overhead.sh`
- 入口：`http://152.136.20.86`（公网 IP 的 80 端口，经 Nginx 转发至 ARServer）
- 工具参数：`wrk -t2`、每个压测点 30 秒、客户端超时 5 秒。
- 并发梯度：10、20、50、100。
- 路径：直接路由回调 `/api/scenes`、静态首页 `/`、动态参数路由 `/api/scenes/1`、携带 `Origin` 的动态路由。

本报告测量的是公网 HTTP 端到端链路，包含客户端网络、云服务器网络、Nginx 和 ARServer；不是 ARServer 的纯本机 I/O 吞吐上限。测试输出未提供云服务器 CPU、内存、带宽、Nginx 日志状态与缓存状态，因此不能据此定位瓶颈来源。

## 分析与结论

1. **稳定工作区间为并发 20～50。** 四类路径在并发 20 时达到本次测试峰值，RPS 范围为 1,055.35～1,089.69；并发提升到 50、100 后，吞吐没有继续增长。
2. **并发 100 已出现尾延迟和超时。** 四类路径的 P99 升至 2.17～2.47 秒，并分别出现 8、12、20、28 个客户端超时；不应将并发 100 的结果作为稳定容量结论。
3. **公网链路主导了本次延迟。** 并发 10 时各路径 P50 约 10 ms，但 P99 已约 203～207 ms；静态、直接回调和动态路由的结果接近，说明当前数据不能证明某一条应用路径是主要瓶颈。
4. **中间件开销在并发 20 下未出现明显吞吐下降。** 携带 CORS 请求头并写入访问日志的路由为 1,062.29 RPS，接近同一路由不显式携带 `Origin` 时的 1,055.35 RPS；但单轮 30 秒测试不足以得出严格性能差异结论。

## 可用于简历或 README 的谨慎表述

> 在公网 HTTP 链路（客户端 → Nginx → ARServer）、`wrk -t2`、30 秒压测条件下，`/api/scenes`、静态首页和动态场景接口在并发 20 时达到约 1.05k～1.09k RPS，P50 约 10～11 ms，未出现客户端超时；并发提升至 100 后吞吐未继续增长且 P99 超过 2 秒，因此将 20～50 并发作为当前云服务器配置下的稳定验证区间。

在公网 HTTP 链路压测 GET /api/scenes，并发 100 下稳定达到 4901 RPS，P99 延迟 40.88 ms，30 秒内无超时及错误响应。

该表述必须与云服务器规格、压测客户端位置、Nginx 配置、日志开关和缓存状态一并记录，不能与本机 WSL 压测数据混用。

## 下一轮验证

1. 在压测期间记录云服务器 CPU、RSS、网络吞吐、Nginx 状态码与 ARServer 日志，定位并发 100 的排队或网络瓶颈。
2. 从独立压测机重复运行 3 次，取中位数，排除单次公网网络抖动。
3. 分别测试 `127.0.0.1:8080` 与公网 Nginx 入口，区分 ARServer 本身、Nginx 与公网网络的影响。
4. 在有效测试 Token 下运行 `benchmark/ar_api.sh`，单独记录缓存 Session 读取和场景成员轮询的业务接口数据。
